# 미스터리 파일 운영

## 공개 범위

290~300레벨의 전투력을 날짜·직업·월드별로 비교합니다. 일반 월드와 에오스·핼리오스를 분리합니다. 현재 실제 기준일은 2026-10-19이며 API 검증 대상은 165,274명(일반 154,251명 / 에오스·핼리오스 11,023명)입니다. 후보 조회는 종료되었지만 후보 목록 밖 캐릭터·API 미제공 대상이 있어 수집본 내 순위로 표시합니다. 가상 순위·대체 이미지를 만들지 않습니다.

이전 285레벨 수집 작업의 후보 741,867명 중 363,503명을 실제 조회했습니다. 최소 레벨을 290으로 변경한 뒤 탐색 경계 미만의 미조회 378,364명은 skipped로 구분했고 조회 인원에 넣지 않았습니다. 이미 수집한 낮은 레벨 기록과 원래 체크포인트는 비공개 PC에 보존했습니다. 최초 384명 시험 표본은 공개 순위에 사용하지 않습니다.

## 데이터 기준과 수집

후보 이름 탐색에만 ranking/overall API를 사용합니다. 앞으로 탐색은 289레벨을 경계 완충 범위로 포함하고 인위적인 인원 제한 없이 페이지를 확인합니다. 실제 등재 레벨·직업·월드·이름·코디는 같은 날짜의 character/basic, 전투력은 같은 날짜의 character/stat 전투력 정수값으로 확인합니다. 경험치 랭킹 순위로 시상식을 결정하지 않습니다. 날짜가 다르거나 API 값이 없으면 채워 넣지 않습니다.

키는 기존 개인용 프로그램의 로컬 설정을 통해 메모리에서만 재사용합니다. Python 수집 소스·설정·로그·원본 JSONL·SQLite·캐시는 공개 저장소 밖에 둡니다. 공개 PC 2.0.4 ZIP, Android 1.0.5 APK, releases.json과 CNAME을 보존합니다.

## 매일 축적

이 대화에 매일 오전 6시(Asia/Seoul) 전날 데이터를 수집하는 로컬 예약을 등록했습니다. PC와 데스크톱 앱이 실행 중이어야 합니다. 비공개 run_daily.py는 누락 날짜를 실제 API 조회로 보충하고 체크포인트를 이어받으며 검증본을 날짜별로 저장합니다. 중복 실행은 잠금으로 막습니다. 예약의 범위는 수집·검증·로컬 저장까지이며 매일 PR 자동 생성·병합·배포는 아직 승인되지 않았습니다. 현재 공개판 배포와 구분하세요.

## 공개 파일 준비

```text
node scripts/publish-mystery-index.mjs 검증본.jsonl 완료기록.json 저장소경로 --archive
```

기본값은 pending/error가 남은 작업의 공개를 거절합니다. 사용자가 중간 공개를 요청한 경우에만 --allow-partial을 명시하며, 페이지에 수집 중임을 표시합니다. 검사 후 전용 개발 브랜치/PR을 만들고 CI 성공을 확인한 뒤 배포합니다. 수집 실패 시 이전 공개본을 유지합니다.

```text
npm test
node scripts/check-mystery.mjs
python -X utf8 tests/check_site.py
```

비공개 audit_public.py로 압축을 해제한 데이터까지 실제 로컬 키와 비밀정보 포함 여부를 검사합니다. 공개 원본에는 허용한 캐릭터 필드만 남깁니다. PC 검색 결과의 수동 반영은 scripts/import-mystery.mjs와 data/mystery-template.csv를 사용합니다. 홈페이지의 내 파일 미리보기는 기기에서만 처리하며 업로드하지 않습니다.

## 날짜별 저장 구조

mystery-config.json의 staticCatalog가 data/mystery-dates.json을 가리킵니다. catalog.latest가 최신일이고 dates[].index가 해당 날짜의 변경 불가한 목록을 가리킵니다. 선택한 날짜가 없으면 미수집으로 표시하며 다른 날짜로 대체하지 않습니다. 공유 링크는 date=YYYY-MM-DD를 지원합니다.

schema_version=2 목록은 query별 레벨 인원수와 상위 10명 참조를 저장합니다. 캐릭터는 날짜별 공유 풀에 한 번만 저장하고 gzip/base64 JSON으로 압축합니다. 브라우저는 선택 부문에 필요한 풀만 읽고 검증합니다. 레벨별 TOP 10의 합집합은 임의의 레벨 구간 TOP 10을 정확히 보존합니다. 표시 인원은 전체 API 검증 수이며 저장된 상위 행 개수와 구분합니다. JSON/CSV 다운로드는 선택한 검증 기록으로 기기에서 생성합니다.

새 파일을 모두 기록한 뒤 catalog를 원자적으로 교체합니다. 과거 날짜와 수정 전 목록은 보존하며 과거 날짜를 추가해도 최신일이 뒤로 가지 않습니다. 공개 data가 800MiB를 넘으면 catalog를 바꾸기 전에 중단하며 과거 기록을 자동 삭제하지 않습니다. 장기 운영 전에는 날짜별 풀을 별도 저장소로 옮기거나 준비된 cloudflare/schema.sql 및 mystery-worker.js의 날짜 조회 계약을 확장하세요. Worker/D1은 아직 연결하지 않았고 현재는 GitHub Pages만 사용합니다. 키는 추후에도 Worker secrets에만 둡니다.
